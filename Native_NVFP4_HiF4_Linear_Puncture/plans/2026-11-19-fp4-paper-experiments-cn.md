# NVFP4 转 HiF4 与 MXFP4 的论文主实验

2026-11-26，正文表 3（M2）采用六任务平均正向损失 $L_6$。GSM8K、GPQA Diamond、LiveCodeBench v6 各取 1234、1235、1236 三个完整种子的均值；ARC-C、OpenBookQA、BoolQ 各取 seed 1234 的一次全量成绩。前两项 QA 用 acc_norm，BoolQ 用 acc。用六个任务各自的未舍入得分与同模型原生参照配对，逐项取正向损失后等权平均；附录展开六项得分、轮数和 TP。表 1、表 2 的共同方法仍按九任务汇总。

本轮对象是 Nemotron 9B 与 QUASAR 4B。每个模型各做 H06、H18、M06、M07、M08 五个配置，六任务共 12 个任务种子轮次，新增上限合计 120 轮。H06 的 full 逐组尺度搜索和 H18 的逐矩阵常数搜索都仅处理权重，激活保留原有 HiF4 G64、标准常数 7 和阈值 4/2；三种 MXFP4 方案分别在权重与激活上实施。新评测用本机 TP1。按相同输入、采样和评分设置复用已有结果，TP 差异如实记录。外机报告已覆盖全部 12 个原生参照得分及 18/24 个直转得分，Nemotron 9B 直转 HiF4 与 QUASAR 4B 直转 MXFP4 各有三个推理均值待回传；本机不排原生或直转的重测。[外机复用来源](../results/paper_baselines/external_20261125T021000Z/report.txt)

### 新增 Q4Q 的接入与证据边界

2026-11-20 已核对上述固定 revision 的公开配置和权重索引，200个文本投影均带 `weight_global_scale` 与 `input_global_scale`。该模型使用 `compressed-tensors / nvfp4-pack-quantized`。现已在 [paper_baselines/checkpoint.py](../../fp4_convert/experiments/paper_baselines/checkpoint.py) 接入其字段与全局尺度语义；200个投影各抽取8行，与compressed-tensors的解码结果比较均相同。完整融合导出已覆盖200个源NVFP4投影，Gated DeltaNet与普通注意力、共享embedding/head的融合等价性已有检查；方法短测与正式结果分别记录。GPTQ使用稠密投影的全部有效token，MoE全专家覆盖规则不适用于该模型；matrix_norm沿用预算与目标，具体层/norm映射待验。

发布方说明，部分非Blackwell路径会回退为仅权重量化。因此Q4Q的原生参照须核对200个目标投影确实执行源NVFP4激活量化，不能把W4A16回退结果当作W4A4基线。现有旧Qwen3.5-4B结果来自其他权重/协议，不作为QUASAR发布版本的已有分数。当前权重已下载并按固定revision完成19个文件校验，已完成解码、融合导出与两目标格式的校准短测。完整运行证据和正式队列状态见[本次记录](../../docs/experience/records/fp4_single_methods_20261120.md)。总规划28个基础配置，最多27次转换/校准、532个任务轮次；本阶段只推进小模型单项。参考[发布说明](https://huggingface.co/QUASAR-QAT/Qwen3.5-4B-QUASAR-NVFP4-W4A4)、[本次元数据快照](../results/paper_experiment_inventory/20261120/quasar_qwen35_4b_source.json)和[既有执行边界经验](../../docs/experience/lessons/fake_quant_boundaries.md)。机制定位仍先用Q30，235B仍只验证最终流程。

### 运行前需要落实的配置

| 当前发现 | 对实验的影响 | 后续动作 |
| --- | --- | --- |
| `main.py` 的 temperature/top_p 默认是 0.7/0.8；未提供显式 seed CLI，底层 vLLM 配置默认 seed=1234 | 裸调用不能实现官方采样和三个不同种子 | 在正式入口显式传递采样与生成 seed，并核对最终引擎配置；本次只记录需求，未改运行代码 |
| `main.py` 默认 max_new_tokens=32768，会覆盖任务自身 generation size | “框架默认”与“本地包装入口默认”不是同一设置 | 用户已明确统一输出32768/context40960；沿用默认任务prompt/评分，固定实际数据及题数，并记录真正传给采样器的参数，检查没有截断题干 |
| 当前 GPQA 默认任务读取 HF，已有 ModelScope 入口使用自定义任务 | 直接复用旧入口会混入不同 prompt/scorer | 仅做 ModelScope 数据适配，保持锁定默认任务的 prompt、选项处理与评分 |
| 多生成数、样本数可能由任务或包装入口控制 | metric 名称不能证明每题生成次数；旧 MMLU-Pro 的 300 题限制不能带入正式实验 | 核对实际题数、每题生成数和三种 seed，独立保存缓存及原始输出 |
| N9/N30/Q30已有 CPU/局部链路证据；Q4Q只有公开元数据核验，接入待做 | 现有工程证据不覆盖新增QUASAR版本 | Q4Q先适配，再按正式环境、完整模型和真实目标路径做必要短测；其他模型补齐正式GPU链路 |

历史结果只有在模型、转换范围、题目、prompt、评分、生成 seed 和实际运行条件匹配时才能进入同一主表。新口径下，旧 seed=1234 的五轮结果**最多提供一个预先指定的 1234 轮次**；1235/1236 必须补测。选轮依据是既有轮号和完整性，不按分数挑选。旧 AISBench prompt 生成与新默认 prompt 不匹配时需要重新推理，不能靠重评分补救。[评测协议与缓存经验](../../docs/experience/lessons/evaluation_evidence.md)

### HiF4 逐权重矩阵常数搜索（E3b，2026-11-20 确认）

用户最终确认：转换时只读取权重，以量化重建MSE最小为准，对每个权重矩阵独立搜索一个共享常数c；激活保持标准c=7。这一口径替代此前“允许真实校准文本”和“跨模型共用一个常数”的讨论，属于**免训练、无需校准文本**的离线权重优化。暂称“HiF4逐矩阵常数搜索”，与UOS在尺度选择规则这一层面比较，不称HiF4-UOS或理论最优。[MXAttention §4.1](https://arxiv.org/html/2607.24377v1#S4.SS1)

**目标与粒度。** 对原生NVFP4解码得到的每个完整逻辑权重矩阵W，选择 `c_W* = argmin_{c∈C} ||Q_HiF4(W;c)-W||_F² / numel(W)`。每个矩阵内所有64元素块共用该c，但各块仍按自己的amax生成S0；不要求不同矩阵、层或模型共用c。MoE每个专家的gate/up/down矩阵分别选参；引擎融合的QKV或gate/up、TP切片与转换分块不改变逻辑矩阵粒度，分块计算时汇总整矩阵误差后选一个c，padding不计入误差。该单参数候选比较可直接枚举取最小，不作梯度训练，也不使用Hessian、激活或层输出误差选值。

**量化规则与搜索预算。** 仅改变 `S0 = E6M2(BF16(amax64 × BF16(1/c)))` 中的常数，保持G64、E6M2、S1P2、原舍入与阈值4/2；两级微指数按新S0重新计算。初始候选建议 `C={6,6.25,…,8}`，共9项，包含标准7。先完整比较这9项；扩大范围或增加精搜另记预算，不把当前集合最优写成连续域理论最优。相同MSE优先选7，其次选离7最近者，仍相同取较小c，保证复现。所有候选始终从同一份W出发，不能依次对前一候选的QDQ结果再量化。选中结果在同一权重MSE目标下应不劣于包含在集合中的c=7，但下游精度不保证提升。

**先转换，后评测。** 九个候选只计算权重误差，不各自运行九项任务。记录每矩阵的c、候选MSE、实际S0改变比例、截断率、非零变零率和搜索时间。激活不搜索，不占用S1K校准文本；如后续用真实输入检查层输出，仅作诊断，不据此重新选c。选定的量化权重冻结后按原九任务协议评测，不使用测试得分选值。仅当整套权重与推理规则经核验等同已有配置时，复用对应完整结果。

同一配置在同一台机器完成所有任务和seed，具体空闲卡组可替换；新任务的TP、KV、batch和长度须与该模型的正式协议一致。不能为凑满12路而缩短生成、减少题数、改变采样或让两个任务重叠占卡。A800上的QDQ/浮点计算用于数值精度比较，计时标明实际后端，不称为原生FP4硬件吞吐。三台同型号机器便于统一执行条件，但仍记录软件、数据与数值路径；目前没有足够实测吞吐估算完成天数。

A向B/C提供模型与任务版本、真实题目/选项/prompt及token摘要、采样与长度、TP/KV/batch、数值后端和完整基线输出；B/C返回相同结构的逐任务逐seed结果、转换/校准成本、权重摘要与覆盖记录。不同硬件上先验证实际数值路径，必要时用同输入的轻量交叉检查定位差异，不自动为每台机器重复跑整套基线。每个配置/seed使用独立预测缓存，已有重构模型复制后只补评。[评测与缓存经验](../../docs/experience/lessons/evaluation_evidence.md)

E0的共享协议由A统筹，B/C各自验证目标格式；E13的转换、校准、导出、存储和在线开销由配置主责机器随实验记录，不另加整套下游评测。入选流程的目标硬件性能实测需对应硬件，三台A800的仿真耗时单列。实际主机对应或外机完成表补齐后，只调整物理对应、并行度及尚未启动的完整工作包，不改变实验设置或重复已完成结果。上述为总体分工；当前服务器先准备并验证两个小模型的单项方案，MoE单项暂缓。

1. **先建立四个模型的原生与直接转换参照。** 两格式都用各自完整的目标投影。Qwen3-30B-A3B 的引言对照按[全量直接转为 MXFP4 的精度补测计划](qwen3_30b_a3b/2026-11-19-qwen3-30b-a3b-full-mxfp4-direct-loss-plan-cn.md)执行。论文只采用全量转换的数字。
2. **先在两个小模型上完成单项对照，MoE结果留空。** 共同比较固定同一模型的输入与量化范围。BRQ 随机块大小匹配目标分组，记录随机符号、融合和执行位置。单用 GPTQ 时关闭额外旋转。AWQ 沿用原方法搜索通道尺度。搜索时仅将缩放后的权重按目标格式量化，在原校准输入上比较输出误差。尺度确定后，在推理时对输入作逆向缩放，再按 HiF4 或 MXFP4 量化激活。SmoothQuant 按校准激活和权重的通道峰值确定尺度，两组均记录尺度的应用位置。各自保存目标权重并核对导出、重载后的实际执行值。[BRQ](https://arxiv.org/abs/2511.04214) · [GPTQ](https://arxiv.org/abs/2210.17323) · [AWQ](https://arxiv.org/abs/2306.00978) · [SmoothQuant](https://arxiv.org/abs/2211.10438) · [MXAttention](https://arxiv.org/abs/2607.24377)
3. **先解释旋转的差异，再比较组合。** 补齐下文第四章的 norm 融合和矩阵对照。先以 Qwen3-30B-A3B 的真实输入定位误差，再在四模型九任务上检验要写入指引的组合及其直接前项；不能以局部误差替代任务收益。校准数据与开发、测试题独立，冻结划分、训练量和可搜索的参数。Qwen3-30B-A3B 的 GPTQ 与 A20 沿用同一批 128 条 S1K 训练序列，A20 另用 32 条验证序列选优。其他模型共享校准文本划分时分别报告实际 token 数、模块覆盖和额外验证成本。[原 HiF4 补充计划](qwen3_30b_a3b/2026-11-16-thesis-format-conversion-supplement-plan-cn.md) · [量化导出与覆盖经验](../../docs/experience/lessons/fake_quant_boundaries.md)
4. **定下流程，再验证 235B。** 四模型逐任务报告增量，比较同等校准预算下的损失与成本；排序不一致时标明适用条件。规模验证前冻结每种格式的一套流程，含转换范围、尺度、旋转、校准数据规则与预算。235B 只比较原生参照与这两套流程；单项搜索和机制消融留在主实验。若训练或导出完成而尚无九项任务得分，规模验证仍待完成。[235B 迁移经验](../../docs/experience/lessons/model_transfer_execution.md)

## 按章节预留的实验与展示
