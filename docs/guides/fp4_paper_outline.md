# FP4 格式转换论文大纲

第三章先用 Nemotron Nano 9B 和 QUASAR Qwen3.5-4B 比较单项方法。两款 30B MoE 模型的单项实验暂缓，其九任务得分、尺度与旋转对照和 Qwen3-30B 的融合诊断列入附录。第五章的校准精度与准备成本表只用 Qwen3-30B-A3B。正文、图表和附录均直接写方法名，组合写出所用的各项方法。BRQ 指融合归一化参数的随机 Walsh–Hadamard 块旋转。保留归一化参数的旋转对照在 HiF4 和 MXFP4 中分别称为“在线 DH64”和“在线 DH32”。

**论文题目**　面向异构 FP4 格式的低成本模型迁移：从免训练适配到局部重构

**确认日期**　2026-11-20（调整第三至六章的推进顺序，以 QUASAR Qwen3.5-4B W4A4 替换 Qwen3.8-27B，主实验采用四个模型）

本文从实际部署出发。手中只有已发布的 NVFP4 权重，需要把模型转为 HiF4 或 MXFP4，怎样以较低成本保住任务精度？论文的贡献是用对照实验给出可操作的转换指引，让读者判断**哪些手段可以直接用，哪些叠加后还有收益，以及现有精度不够时下一步值得做什么**。两种目标格式沿这三个问题并行展开，各自给出有证据支持的搭配和适用条件。

两条路线均转换源模型在文本推理中原用 NVFP4 的全部线性投影及其输入激活。只有这一范围的任务得分可用于论文的图表和结论。本稿的正式比较采用 Nemotron-Nano-9B-v2、Nemotron-3-Nano-30B-A3B、Qwen3-30B-A3B 和 QUASAR-QAT 发布的 Qwen3.5-4B-QUASAR-NVFP4-W4A4 四个主模型、两种目标格式和九项任务。五项生成式推理任务各取三轮均值，MMLU-Pro 每轮使用全部 12,032 题。235B 留作定案后的规模验证。普通 QA 使用 lm_eval，五项推理任务使用锁定版本 lighteval 的默认任务、prompt 和评分；普通 QA 用 seed=1234 跑一次，五项推理任务用 1234、1235、1236 各跑一次。GPQA Diamond 使用 ModelScope 的 198 题，各模型采用官方推理参数。模型清单、主基线、候选组合和每条主张的证据列在[论文主实验计划](../../Native_NVFP4_HiF4_Linear_Puncture/plans/2026-11-19-fp4-paper-experiments-cn.md)。

## 1. 引言

从 LLM 量化降低推理成本写起，交代 4 位计算已有硬件支持，以及各家芯片支持的 FP4 格式有所不同。接着以已发布的 NVFP4 模型为例，简要交代同一厂商不同代际芯片的原生计算支持也有差异，再引出在昇腾和 AMD 平台部署时分别转向 HiF4 和 MXFP4 的需求。前两段只交代背景，把编码和分组细节留给第 2 节。

## 2. 格式差异与转换问题

全章不设编号小节。章首承接图 1 中实际观察到的精度变化，提出一个具体问题：同样用 4 位编码，为什么格式转换还可能引入误差？用图 2 贯穿下面三段。

1. 从图 2 中的两个权重出发。第 1 个权重为 6，第 17 个权重为 0.25。说明 NVFP4 怎样用元素编码、块尺度和张量尺度表示权重，以及这两个权重为何可以各用一个块尺度。
2. 转为 MXFP4 后，两个源块合为一个块。沿用这两个权重，解释为什么即使元素仍用 E2M1 编码，一旦共用同一个尺度，6 和 0.25 就无法同时精确表示。
3. 转为 HiF4 后，解释 64 个权重共享基础尺度、每 8 个和每 4 个权重再分级调整尺度的方式。结合 S1P2 的可选值，展示同样两个权重怎样在不同子组中保留原值。由两条路线归纳出，整组权重能否同时保留原值，取决于元素的可选值和尺度的共享方式。

章末接着问，已有的训练后量化方法能否减小重新量化带来的精度损失？用 HiF4 和 MXFP4 的量化研究交代依据，再把问题落到本文的条件：从已发布的 NVFP4 权重出发，这些方法能比直接转换保留多少精度？让第三章用实验回答。

## 3. 现有方法能恢复多少转换精度？

承接第二章，在四个主模型上分别比较 NVFP4 转 HiF4 和 MXFP4 的结果。先交代同源、全量转换和九任务设置，再给出 BRQ、独立 GPTQ、AWQ 与 SmoothQuant 的逐任务收益和校准成本。用原生模型衡量转换损失，用各自的直接转换版本衡量单项收益。

随后补上格式特有的方法。HiF4 比较直接转换与只做权重层级尺度贪心搜索，说明只读取权重能恢复多少精度。MXFP4 比较直接转换、UOS、G256 和 G512，并交代外层尺度带来的存储、部分和缩放与算子要求。二级尺度采用 FP32 外层尺度时，每个权重增加 32/G 位，G256 和 G512 的完整组平均位宽分别为 4.375 和 4.3125 位，实际文件大小和推理性能另测。

章末从结果中提取需要进一步解释的现象。如果融合版旋转收益有限或退化，交代具体模型、格式和任务，再引出第四章。GPTQ 的跨任务收益、AWQ 与 SmoothQuant 的效果、UOS 与尺度搜索的作用均按实测填写。现阶段把这些问题作为待检验预期。

HiF4 逐矩阵常数搜索在转换时为每个完整权重矩阵选一个共享的 $c$，使解码后的 NVFP4 权重重新量化时的均方误差最小。激活保持标准 $c=7$。这一搜索只读取权重，无需训练和校准文本。行文中说明它与逐组权重尺度搜索的粒度差异，以及它与 UOS 在常数选取和作用对象上的差异。四个模型沿用相同的搜索规则，分别报告所选常数和实测任务精度。

正文用任务得分比较共同基线和格式特有的方法。附录补充 Qwen3-30B-A3B 在固定 R64 时的权重重建误差，分别列出注意力和路由专家在标准尺度与逐组搜索下的 NMSE。逐矩阵常数搜索的曲线、常数分布与下游验证另列。

## 4. 旋转在什么条件下有用？

先研究 norm 融合，再研究在线旋转的矩阵选择。每一步由前一组结果引出，实验内容紧跟所要解释的现象。

1. **norm 融合改变了什么。** 固定真实输入、目标量化器和随机旋转矩阵，比较保留／融合通道增益与无旋转／固定旋转的四种设置。量化前核对等价输出，量化后检查组内相对幅值、尺度选择和层输出误差。分别只量化权重、只量化激活与同时量化两者，定位影响来自哪一侧。再把直接转换、融合版块旋转和在线块旋转的任务得分并排比较。
2. **保留 norm 后如何在线旋转。** 权重在转换时旋转，激活在推理入口旋转，解释配套变换保持量化前输出的关系，并说明在线成本。`paper_baselines` 的 `brq` 对应在线配置，`brq_fused` 对应完整融合配置；分别验证和导出，实验结果按各自实际操作命名。
3. **标准 Walsh 对均值分量做了什么。** 从一块真实激活出发，并列原始输入、标准 H、输入带随机符号的 DH 和 R32/R64。共用坐标轴，标出最大通道能量占比与量化误差。随后用更多激活按均值能量占比分桶统计，说明样例代表哪些输入。随机符号方案单独比较，并记录种子差异。
4. **为什么选择 R32 和 R64。** 给出基于 R4 的构造、正交性和常量响应，再分别用 G32 与 G64 的同条件对照检验真实量化误差和任务收益。常量响应的推导只能解释该分量，真实输入还需考虑残差。构造的新颖性结合已有文献界定。

融合与在线旋转的整模型对照选用 Qwen3-30B-A3B 的 MMLU-Pro 和 LiveCodeBench v6，各报告统一设置下三个生成种子的均值。矩阵选择表另设两列展示该模型同一历史首轮的逐任务得分。两部分分别支撑融合方式和矩阵选择的比较。真实激活样例及均值分桶统计随实测补入。

## 5. 哪些手段值得组合，精度不足时再加什么？

首先比较无需校准样本的组合。HiF4 用直接转换、只搜索尺度、只用 R64、R64 加搜索四组判断是否互补。MXFP4 比较 R32、UOS 与两者组合，再在同一 R32 加 UOS 配置上分别加入 G256 或 G512。每次增加操作都与其直接前项比较，报告精度增量和新增开销。

接着用 Qwen3-30B-A3B 做校准消融。HiF4 以原生、直接转换与固定 R64 为参照，考察 R64 加逐组尺度搜索、加 GPTQ 或逐层重构对不同任务的影响。比较重构所用的校准文本时，S1K 和原生模型自生成序列均训练 20 轮。MXFP4 在全部目标投影上选定免校准组合，再考察该组合加入 GPTQ 前后的差异，并列独立 GPTQ。转换与独立开发集评测分列计时，转换包含导出，层内验证计入重构，共用的语料生成开销另计。[HiF4 补充实验计划](../../Native_NVFP4_HiF4_Linear_Puncture/plans/qwen3_30b_a3b/2026-11-16-thesis-format-conversion-supplement-plan-cn.md)

最后在四个主模型上确定两种目标格式各自的流程，固定规则和预算，再用 Qwen3-235B-A22B 验证。235B 只测试最终选定的两套流程和对应原生参照。

第五章正文保留一张校准精度与准备成本表。已有 HiF4 对照取各方法均已完成的第一轮，MMLU-Pro、LiveCodeBench v6 和 GSM8K 使用生成种子 1234，ARC-C、ARC-E 使用种子 42 并取 acc_norm。九任务主比较仍取既定轮数。附录的 HiF4 组合表单列 Qwen3-30B-A3B 在同一历史首轮的 MMLU-Pro 与 LiveCodeBench v6 增量。重构预算表用独立开发集的 64 道数学题和 64 道编程题比较不同训练轮数和取样方式，并单列转换及开发评测成本。待补实验包括 MXFP4 全量校准的成对结果、其余方法组合及 235B 验证。

逐矩阵常数搜索比较四种设置，分别是标准 HiF4、只搜索 $c$、只用 R64，以及先做 R64 再搜索 $c$。各表共用单项结果。对旋转后的权重仍按相同的候选集和均方误差目标选取 $c$，激活沿用标准 HiF4。该组合无需校准文本，单独记录离线搜索成本。实验数量与预算见[主实验计划中的 HiF4 逐权重矩阵常数搜索](../../Native_NVFP4_HiF4_Linear_Puncture/plans/2026-11-19-fp4-paper-experiments-cn.md)。
