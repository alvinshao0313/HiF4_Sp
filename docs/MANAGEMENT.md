# 文档管理规范

适用范围：`/home/shaoyuantian/program/HiF4_Sp`。协作规则只维护于根目录 [AGENTS.md](../AGENTS.md)；本文件规定文档的归属、导航和维护。迁移其他项目的习惯时，来源项目保持独立，正文落在明确指定的目标项目中。

## 文档归属

| 类型 | 正文位置 | 内容与边界 |
| --- | --- | --- |
| 统一导航 | `docs/README.md`、`docs/INDEX.md` | 前者按主题引导，后者自动列出自有文档；不复制正文 |
| 当前指南 | `docs/guides/`、模块或实验的 `README.md` | 安装、用法、算法和实现约定；贴近源码的 README 保留原位 |
| 可复用经验 | `docs/experience/lessons/` | 问题、证据、解释、有效做法、适用边界和来源 |
| 实验与维护记录 | `docs/experience/records/` | 按研究主题和日期记录配置、结论、证据位置；不把计划当实测 |
| 方案与历史 | `docs/experience/history/`、现有 `plans/`、`PLAN*.md`、`archive/legacy/` | 标明适用模型、时间和替代关系；方案存在不代表执行授权，历史命令不代表当前入口 |
| 运行证据与生成报告 | 现有 `results/`、`.result/`、`reports/` | 与配置、原始指标和日志一起保留，由导航引用；不手改生成数据，不移动活动实验 |
| 工具交接状态 | `.ai-bridge/` | 按需追溯，不当作现行规范或实时状态，不默认全量读取 |
| 第三方文档 | `3rdparty/`、`NVFP4/llm-compressor/` | 保持上游布局和维护方式；本项目只提供入口，不批量改写 |

根目录 README 负责介绍项目与常用命令；实验 README 说明该实验如何运行。两者链接统一导航，不再各维护一套全仓库清单。旧路径可保留只含链接的导航页，正文仅维护一份。

## 阅读与更新

1. 每个任务先读 [文档入口](README.md)，再按主题查阅。默认检索指南与经验；需要数值、失败证据或计划沿革时再扩大范围。
2. 设计或调整实验前检索 [经验库](experience/README.md)。命中后读取来源与适用边界，说明参考经验、条件差异及处理方式；没有命中则如实说明。
3. 同一问题或实验优先更新现有正文。新增主题才增加文档；不要按每步操作建立计划、最终版或重复总结。
4. 运行记录写明模型与数据、实际配置和种子、命令、代码版本或文件哈希、日志和指标位置。区分历史事实、当前核验、推断及尚未验证的假设。
5. 实验收尾时总结结果、检查是否有经验增量并更新导航；没有新增经验就说明，无需强建文件。经验链接原记录，记录链接相关经验。产物清理遵守 HiF4_Sp 自身的授权边界，不引入其他项目的自动删除权重规则。
6. 新增、移动、修改标题或归档文档后，在仓库根目录的 `hif4` 环境执行：

   ```bash
   python tools/docs.py index
   python tools/docs.py check
   ```

`index` 只刷新 `docs/INDEX.md`；`check` 检查索引是否同步及 Markdown 本地链接目标是否存在，不执行历史命令，不验证外网、标题锚点或实验正确性。搜索和索引包含被 Git 忽略但仍在本机的自有结果文档，因此不同机器的索引可能不同；记录未随仓库分发时需读取者获取对应产物。
