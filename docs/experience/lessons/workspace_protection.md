## 目录名称不能决定是否可移除

旧实验目录可能含当前主线的共享实现。既有清理保留了 `experiments/diag_gradient/r64_transform.py`、`experiments/long_trajectory_stability/real_vllm_hooks/`、`HiFloat4/hif4_scale_threshold_optimization/src/` 和 `NVFP4/`；旧 8B 的其他源码才进入 `archive/legacy/`。

整理前检查当前 import、脚本引用、实际进程命令和后续任务。活动 progressive 的源码、配置、结果与 checkpoint 作为整体保护，不能因其属于某个历史父目录而一起移动。

## IDE 排除与物理删除分开

`3rdparty/vllm` 和 `3rdparty/lighteval` 是共享依赖，VS Code 的搜索或 watcher 排除不代表它们已从磁盘删除。目录不可见时先检查磁盘和配置，再解释状态。

## 原始证据与授权保留边界

历史清理释放空间的数字只描述对应操作，不能再计为本次收益。HiF4_Sp 默认保留已有结果；不把 VAELLM 的自动清理授权带入本项目。源码、结果是否继续使用必须基于当前证据判断，旧计划或旧清理记录不是新删除授权。

2026-09-24 的文档整理阶段只迁移正文和修复导航，未清理实验产物。同日后续获用户明确要求的清理另见下文。

## 完成训练后的恢复状态与空间统计

[2026-09-24 清理记录](../records/maintenance/2026-09-24-history-cleanup.md) 核实 residual LoRA 三组均完成 48 层；终层 `resume.pt` 仅保存下一层编号、轮次和 hidden，后续导出从初始化及逐层 `selected.pt` 读取参数。因此本轮在保留全部训练权重、指标和日志后，删除了三份冗余恢复状态。

这个判断依赖实际文件内容、完整的完成记录和导出调用链，不能推广成按文件名删除所有 resume。未完成训练、约定的续训或其他消费方仍需要的状态必须保留；训练完成也不代表下游评测完成。

盘点还发现部分模型文件已有多重硬链接。计算清理收益时要核对 inode、link count 和实际分配块；删除一个仍有其他硬链接的副本不会释放对应数据块。共享磁盘剩余空间会随其他任务变化，不能直接把 `df` 差值当成本次删除量。

## Git 忽略规则不能代替内容分类

证据状态：[2026-11-18 仓库盘点](../records/maintenance/2026-11-18-repository-organization.md)发现 `**/data/` 隐藏了 `e2e_diag_reconstruction/data/` 中 5 个训练与校准流程直接依赖的 Python 文件。全局 JSON、YAML、`models/` 和 `plans/` 规则也会屏蔽配置、模型实现和协议。

按明确的产物目录忽略权重、日志与缓存，保留源码目录和配置扩展名。修改后检查 `git ls-files --others --exclude-standard` 与代表性路径的 `git check-ignore --no-index`，分别识别恢复可见的源码和本地产物。取消忽略不等于已经提交；新增忽略规则也不能移除已跟踪的客户端状态。

第三方目录还要核对 Git mode：`160000` 是子模块指针，不是普通源码目录。缺少 `.gitmodules` 或完整本地源码时，不能据目录存在宣称干净 clone 已含完整依赖。本次只确认了这些静态问题，没有执行新环境安装验证。

## 路径可读不等于 Git 迁移可用

同日整理把已跟踪的 `HiFloat4/hifx4_npu/` 目录替换为符号链接，虽然文件 SHA256 和路径解析通过，但 Git 索引仍记录旧子文件，编辑器按子文件暂存时实际报 `pathspec ... is beyond a symbolic link`。已恢复原实体目录；报错路径和全部 28 个子文件的 `git add --dry-run` 均恢复退出码 0，内容及原暂存项不变。

未同步调整索引时，不把已跟踪目录替换为指向新位置的符号链接。目录整理除内容一致性外，还应验证编辑器实际使用的逐文件 pathspec。文件本身作为符号链接与穿越父目录符号链接是不同情况；两份评测脚本的叶子链接另行验证，不据此推广目录链接可用。

## 挂起进程仍依赖冻结源码

证据状态：[2026-11-20 暂停与主包迁移](../records/maintenance/2026-11-18-repository-organization.md#2026-11-20-暂停与主包迁移)核对了两组控制器：后续阶段会重新导入模块、启动子进程并比较源码哈希。SIGSTOP 保留内存和显存，不会解除这些依赖，也不是可跨进程退出的恢复 checkpoint。

本次获用户选择后，维护代码迁入 `fp4_convert`，旧源码按原路径、原字节仅留本地；历史计划与结果保持原位。迁移源码时必须区分 `Path.parents` 推导的是源码目录还是历史校准/结果目录，不能只全局替换旧包名。新包测试中拒绝导入旧包，才能发现本机副本掩盖的远程源码缺口。恢复暂停任务前核对 PID 启动时间、进程树和全部冻结依赖；不篡改历史源码哈希绕过验证。

同日恢复的实测边界：约 3 小时 24 分钟后发送 SIGCONT，两组均立即触发 NCCL 10 分钟 collective timeout 和 vLLM RPC timeout。SIGSTOP 保存进程内存，不能据此保证 GPU 通信可跨长时间暂停恢复；整棵进程树挂起也没有冻结通信的超时计时。本次失败的 MMLU-Pro 调用未写出原始生成缓存，进度条上的完成条数不能用于接续。应优先在评测阶段边界协作暂停；已有长暂停失败时保留原日志与目录，用原协议、原冻结源码重跑未完成阶段，复用已完成且证据齐全的轮次，不关闭超时或修改源码哈希来掩盖失败。
