## 追加 FHT32 对照（2026-11-10）

用户确认将旋转替换为标准 32×32 Walsh–Hadamard 并要求四卡并行推理。
新增 RUN 为
`Native_NVFP4_HiF4_Linear_Puncture/results/qwen3_mxfp4/fht32_tp4_20261110T032038Z`，
原三组权重、原始回答及复核结果保留；不重跑已有基线。

新候选为 `fht32`：`H2⊗5/sqrt(32)`，Sylvester 自然顺序，无符号随机化或额外置换。
NVFP4 专家权重按原顺序解码并舍入 BF16，再沿 K32 做 FP32 五级蝶形变换，最后乘
`1/sqrt(32)` 并直接量化。gate/up 和 SwiGLU 后 down 的激活采用相同方向的融合
FHT32＋MXFP4 QDQ；所有其他模块、原生 SwiGLU 舍入、路由和 TP 通信保持不变。
H32 的大小与 MXFP4 分组对齐，但它同时改变了原 regular R64 的矩阵结构，
效果差异不能单独归因于块大小。

沿用 [fake quant 经验](../lessons/fake_quant_boundaries.md)中的 NVFP4 倍率、FP32 旋转边界、
SwiGLU 两次舍入和参数化 packed GEMM；沿用 [评测经验](../lessons/evaluation_evidence.md)
中的实际 prompt/token 检查及独立最终提交复核。新增假设是 H32 的坐标变换能否改善
group32 量化后的 GPQA，局部数值验证不作为下游收益证据。

CPU 的 15 项格式、真实权重、注册和评分回归测试通过。H32 正交性、基向量方向、
K32 分组独立性、乘积恒等式及 FP32 边界已验证。GPU 首次编译发现 Triton 不接受
普通 Python 全局浮点常量；将同一归一化值声明为 `tl.constexpr` 后，实际 H32 基向量
和常量输入测试通过，scale/编码/重建值与参考一致；失败及修复记录保存在 RUN。
direct/R64 在正式局部形状上的 QDQ 输出、编码、scale 和旋转中间值与修改前源码
逐字节相同，证据为 `unchanged_variants_gpu.json`。

正式流程使用 GPU4–7、TP4、batch256、8192 batched tokens、32 GiB BF16 KV/卡，
